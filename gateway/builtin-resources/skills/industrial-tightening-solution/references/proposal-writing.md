# 公开同类方案研究与写法

## 研究目标

研究不是为了找一份方案改客户名称，而是回答四个问题：行业通常解决什么痛点、系统边界通常包含什么、关键指标如何表述和验收、哪些内容必须留作待澄清。

## 来源分级

1. **规范性来源**：国家/行业标准、客户公开技术协议、招标公告与澄清文件。用于约束、验收、资质和术语。
2. **原厂来源**：拧紧工具、传感器、校验设备、服务器/操作系统/数据库厂商的技术手册。用于产品能力和环境条件。
3. **可核验案例**：客户或集成商公开案例，必须保留发布主体和日期。用于场景、架构和实施节奏。
4. **行业文章**：用于关键词、目录灵感和术语发现，不能单独支撑参数、效果或兼容承诺。

检索记录至少包含：`主题 | 查询词 | 链接/文件 | 发布方 | 日期 | 可复用结论 | 不能推导的结论 | 方案引用位置`。

## 项目技术方案标准目录

适用于“拧紧设备 + 软件平台”，按项目规模增减章节：

1. 封面、版本记录、保密与适用范围。
2. 项目背景、现场现状、问题和建设目标。
3. 需求理解与边界：工位、工序、车型/产品、节拍、质量、现有系统、甲乙双方责任、排除项和待澄清项。
4. 总体方案：业务流程、设备/网络/平台分层架构、部署拓扑和数据流。
5. 拧紧工艺与设备方案：工艺策略、拧紧轴/扳手/工装/安全、控制精度、校准、异常处置。
6. 扭矩校验与计量方案：量程、传感器、加载、校验流程、报告、标签、追溯和第三方计量边界。
7. 软件功能方案：工艺、工单、作业引导、防错、设备、用户权限、质量、报表、追溯、报警和运维。
8. 接口与数据方案：MES/MOM/KMIS/LIMS/PLM、协议、数据项、鉴权、失败重试、离线补传和数据归属。
9. 可选专题：生产大屏、数字孪生、信创部署、移动作业、AI/视觉。仅在需求确认后写为建设内容。
10. 非功能方案：网络、安全、性能、可用性、备份、日志、监控、国产化兼容和数据保留。
11. 实施计划：设计、加工/采购、安装、单机调试、联调、培训、试运行、上线、运维。
12. 验收、交付、质保和售后：测试场景、验收标准、文档/备件/证书、服务响应和责任划分。
13. 附录：BOM、参数表、接口清单、部署清单、验收矩阵、术语和参考来源。

## 按场景加写内容

| 场景 | 必写内容 | 常见遗漏 |
|---|---|---|
| 拧紧轴/多轴设备 | 机械布局、工艺策略、同步、认帽、曲线、校准、安全和维护 | 螺栓唯一追溯、多轴异常、中断恢复 |
| 智能扳手 | 工具适配、身份绑定、校验有效期、离线补传和防错 | 结果幂等、工具换人/换工位控制 |
| 扭矩校验台 | 量程/精度、传感器、加载方式、报告和计量证书 | 校验精度与拧紧精度混用 |
| 生产大屏 | 数据源、刷新周期、车间图、角色和异常闭环 | 只画页面，不定义数据链路 |
| 数字孪生 | 模型来源、资产 ID、坐标、状态源、时间一致性和回放 | 静态三维被称为实时孪生 |
| 信创 | 软硬件目标组合、外围驱动、性能、迁移、回退和验证 | 只写“支持国产化” |

## 写作规则

- 每章至少回答“解决什么问题、由谁使用、输入是什么、如何处理、输出什么、失败时如何处理、如何验收”。
- 把“需求”“设计”“已实现能力”“本项目承诺”“待确认”分开写。图纸、参数、案例和效果没有当前项目证据时，使用条件句或待确认项。
- 设备技术协议与售前方案不同：协议写可验收条款、配置和责任；售前方案写价值、路径和总体能力，但两者都不能回避边界条件。
- 对外文档引用外部资料时写清来源；内部草稿保留检索台账，防止后来无法追溯参数出处。
