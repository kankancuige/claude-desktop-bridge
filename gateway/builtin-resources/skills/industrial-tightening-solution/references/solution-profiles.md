# 模块路由与按需组装

本文件不是固定套餐目录。A-D 是可复用的“模块写作 Profile”，用于决定某个模块应该写什么；实际方案以用户明确的模块清单、现场证据和交付边界为准。用户可以提出任意模块组合，也可以只提出一个模块。先装配模块，再生成章节，不要强行给项目贴一个固定类型。

## 一、识别方法

从用户资料中提取用户明确点名的模块、设备、操作者、工艺动作、数据源、外部系统和交付物。根据强特征选择一个或多个模块 Profile：

| Profile | 强特征 | 不足以单独判定的弱特征 |
|---|---|---|
| A 专用拧紧机/拧紧轴 | 桁架、伺服、多轴、同步、认帽、套筒、机械工装、PLC、安全回路 | 只有“扭矩采集”或“拧紧结果” |
| B 智能扳手 + PDA + 装配系统 | 手持工具、PDA/平板、扫码、人员登录、作业引导、工序防错、移动作业 | 只有一把联网工具或一张报表 |
| C 扭矩校验台/检定仪 | 传感器量程、加载机构、校零、正反向、重复性、ISO 6789、证书/报告 | 只有“校准管理”字段 |
| D 生产大屏/数字孪生 | 车间布局、计划进度、工位状态、3D 模型、资产绑定、实时状态、历史回放 | 只有普通统计图或设备图片 |
| 组合装配 | 两个及以上模块有独立业务目标、设备或验收链 | 单一模块附带一个简单终端页面 |

用户明确说出的模块优先于照片和历史资料。无法确定时，不强行分类，输出“已确认模块 + 建议补充模块 + 现场证据 + 会改变方案的待确认问题”。未被用户点名的模块只能作为建议或待确认，不得自动扩大采购范围。

## 二、通用章节骨架

客户版方案保留以下公共骨架，但章节编号和名称可按招标文件或客户格式调整：

1. 项目概述、现状、目标和范围边界。
2. 需求理解与待澄清事项。
3. 总体业务流程、系统边界、架构和部署。
4. 已确认模块的设备、工艺或业务专题。
5. 软件、接口与数据设计（仅写实际范围）。
6. 非功能、安全、运维与部署约束。
7. 实施、交付、验收和服务。
8. 配置、参数、接口、验收矩阵和来源等附录。

内部母版保持完整，用于需求检查和版本对比；对外成稿删除不适用专题，不保留连续多章“本项目不涉及”。若客户目录要求逐条响应，则保留其原章节并写“不适用/无偏离”，同时说明依据。

## 三、Profile A：专用拧紧机/多轴拧紧设备

**适用条件**：交付核心是固定式、移动式、桁架式、机器人式或多轴专用拧紧设备，软件主要服务于设备控制、工艺选择和质量追溯。

**必写内容**：现场与工件边界；螺栓规格、数量和空间；机械结构与可达性；拧紧轴/伺服/传感器/编码器；工装套筒与反力；认帽/定位；预拧终拧与多轴同步；节拍；曲线与判定；PLC/控制器；急停、防碰撞和安全回路；异常、中断和断电恢复；维护校准；结果追溯；设备 FAT/SAT。

**按需加入**：扫码/视觉、自动换型、MES/MOM/KMIS 接口、生产报表、远程诊断、校验台、大屏、数字孪生、信创。

**通常删除**：没有移动作业时的 PDA 章节；没有计量交付时的完整校验台章节；没有真实模型和状态源时的数字孪生专题。

**核心输入**：工件/车型、工位布局、螺栓点位、扭矩角度策略、节拍、可达空间、电源气源、上下游节拍、安全规范、现有接口。

**典型数据流**：`工件识别 -> 程序/车型匹配 -> 设备就绪与安全互锁 -> 定位/认帽 -> 预拧/终拧 -> 实时判定 -> 异常处置 -> 曲线与结果归档 -> 上报`。

**必验收项目**：机械可达性与防护；各轴量程/精度证据；程序切换；正常、欠拧、超拧、滑牙、浮高、未认帽等适用故障；同步和节拍；急停；断电/断网恢复；重复结果防重；曲线与螺栓点追溯；校准与维护模式。

## 四、Profile B：智能扳手 + PDA + 装配管理系统

**适用条件**：操作者手持智能扳手，以 PDA/平板/工位终端完成登录、扫码、工单接收、作业引导和结果确认，后台系统管理工艺、质量与追溯。

**必写内容**：人员/工位/工件识别；PDA 登录和扫码；工单与工艺版本；工步、图文指导和顺序控制；扳手身份、量程、校验有效期和电量；工具与任务绑定；参数下发；结果/曲线回传；漏拧、重拧、错序、错工具、校验过期防错；离线作业、缓存和补传；人工放行和审计；后台查询报表；终端与工具通信；外部系统接口。

**按需加入**：定位、RFID、视觉、工具柜、充电管理、电子签名、附件/工艺文件、生产大屏、数字孪生、校验台、信创。

**通常删除**：机械桁架、伺服多轴同步、认帽机构和专机安全回路；未采购校验设备时不写加载机构和传感器选型。

**核心输入**：终端数量、工具品牌/型号/协议、PDA 系统与网络、扫码规则、人员角色、产品与工步、螺栓点、工艺参数、离线时长、数据保留、现有 MES/MOM/KMIS。

**典型数据流**：`人员登录 -> PDA 扫描工件/工单 -> 获取锁定工艺版本 -> 引导当前工步 -> 匹配并解锁扳手 -> 下发参数 -> 执行拧紧 -> 回传结果/曲线 -> PDA 实时判定与转序 -> 平台追溯/外部系统回传`。

**必验收项目**：账号权限；扫码与错件拦截；正确/错误工具匹配；参数下发；顺序和漏拧防错；合格/不合格/重复结果；换人换工位；校验过期禁用；断网继续/禁止策略；重连补传与幂等；PDA 退出/重启恢复；接口失败重试；人工放行留痕。

## 五、Profile C：扭矩校验台/检定仪

**适用条件**：交付核心是对扳手、拧紧工具或传感器进行校验、比对或检定，并形成可追溯记录、标签或报告。

**必写内容**：适用工具类型；量程覆盖；传感器与等级；加载方式；反力与安全防护；正反向；校零；采样和峰值/跟踪模式；校准点与次数；环境条件；判定依据；标签/报告；标准器证书；工具台账和校验周期；数据归档；过载和异常处置；计量边界。

**按需加入**：自动加载、扫码/刷卡、传感器自动识别、后台计量管理、LIMS/MES/工具管理接口、PDA、信创。

**通常删除**：装配工单和螺栓顺序；专用拧紧机机械结构；没有生产状态数据时的大屏/数字孪生。

**核心输入**：被校工具类型与量程、目标标准/规程、允许误差、校准点、方向、加载方式、传感器配置、证书要求、报告格式、环境和第三方计量边界。

**典型数据流**：`工具识别 -> 校验有效性/任务检查 -> 传感器选择与校零 -> 分点加载采集 -> 误差/重复性计算 -> 判定 -> 报告/标签 -> 工具状态更新 -> 归档/上报`。

**必验收项目**：各量程和方向；校零；示值、重复性及适用指标；手动/自动加载；过载保护；异常数据不落为合格；证书/报告字段；工具状态联动；断电恢复；备份恢复；标准器和溯源证据。

## 六、Profile D：生产大屏/数字孪生

**适用条件**：交付核心是汇聚生产、质量、设备或安全数据进行大屏展示，或以三维资产与实时状态映射形成数字孪生应用。

**必写内容**：受众和使用场景；数据源及所有权；指标口径；车间/工位/车辆或设备对象；刷新周期和延迟；异常闭环；权限；屏幕与分辨率；网络与部署；断流/脏数据提示；历史查询；性能与并发。数字孪生还必须写模型来源、资产 ID、坐标系、节点映射、状态枚举、时间一致性、模型版本和降级方式。

**按需加入**：计划进度、质量、设备 OEE、安灯、安全、能耗、工艺文件、PDA、三维漫游、历史回放、远程运维、信创。

**通常删除**：没有设备采购时的拧紧轴 BOM；没有计量业务时的校验台章节；静态三维展示不能写成实时孪生。

**核心输入**：看板受众、屏幕参数、页面清单、数据源、指标定义、刷新/延迟目标、终端与并发、网络、三维资产、状态源、资产映射和历史保留。

**典型数据流**：`业务/设备数据源 -> 接口采集与校验 -> 指标计算/状态归一 -> 缓存与历史库 -> Web 大屏/三维场景 -> 异常钻取与闭环`。

**必验收项目**：指标口径抽样核对；数据刷新和端到端延迟；断流/异常值显示；权限；目标分辨率；并发与长时间运行；网络恢复；历史查询。数字孪生另验资产映射、状态切换、时间一致性、模型加载、降级和历史回放。

## 七、任意组合的装配方法

组合不是固定 Profile，而是把用户点名的模块按接口装配。先分别保留各模块业务闭环，再合并公共内容：

1. 只保留一套项目概述、总体架构、部署、非功能、实施和服务章节。
2. 每个 Profile 建独立专题，不能把拧紧结果、计量结果和大屏指标混成同一数据对象。
3. 画一张端到端总数据流，再为每个 Profile 画子流程。
4. 建立跨模块接口表：`来源 | 目标 | 触发 | 数据 | 身份键 | 超时 | 重试/幂等 | 失败状态 | 恢复方式 | 验收用例`。
5. 验收矩阵同时包含各 Profile 单项验收和跨模块端到端验收。

以下只是装配示例，不是预设套餐：

- **拧紧机 + 软件平台**：A 为主，加入工艺、追溯、接口和报表。
- **扳手 + PDA + 装配系统**：B 为主，不自动加入 A 的机械专机内容。
- **扳手 + PDA + 装配系统 + 校验台**：B + C，工具唯一 ID 和校验状态是关键共享数据。
- **拧紧设备/扳手 + 大屏**：A 或 B + D，大屏消费业务状态，不参与实时安全控制。
- **拧紧设备 + 数字孪生**：A + D，明确设备节点、状态源、刷新周期和模型降级。
- **上述任一组合 + 信创**：叠加信创约束，对完整软硬件组合做适配和验收。

## 八、横切选项

### 信创

信创不是默认模块。只有用户、招标文件或部署环境明确要求时，才叠加目标 CPU/服务器、操作系统、数据库、中间件、浏览器、密码/证书、外围驱动、迁移、备份、性能和回退验证。不能把“可部署于国产环境”写成已经完成兼容认证。

### 外部系统接口

只有存在系统对接时写具体接口。区分工单/工艺主数据、设备实时状态、拧紧结果、曲线、计量状态和附件文件；明确数据所有权、身份键、时序、幂等和失败恢复。

### 软件终端

PDA、Web、PC、大屏是交互终端，不自动代表独立业务模块。根据操作者、现场网络、屏幕尺寸、离线策略和权限裁剪功能。

## 九、资料稀疏时的补全

只有现场照片和口头想法时，读取 [sparse-input-and-photo.md](sparse-input-and-photo.md)。先建立现场证据表、模块装配表和落地问题表，再写正式方案。历史方案用于补齐章节、设计模式和验收思路，不用于直接复制当前项目参数或客户事实。

## 十、裁剪输出

成稿前输出一个简短的内部“方案装配表”，不必放入客户正文：

`已确认模块 | 建议补充模块 | 暂不纳入模块 | 判定证据 | 必写专题 | 删除专题 | 待确认项 | 跨模块接口 | 验收重点`

裁剪后检查：每项需求是否进入正文或待确认清单；每个设备/软件承诺是否有验收方法；每个跨模块状态是否有唯一身份键和失败恢复；删除章节后是否仍保留完整业务链。
