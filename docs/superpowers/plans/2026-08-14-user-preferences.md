# 用户偏好候选与按需注入

## 目标

为单用户桌面端增加轻量的偏好学习闭环：当用户在不同任务中重复强调明确、稳定的约束时，Gateway 生成非阻塞候选提示；用户确认后按项目或全局保存，并只在与当前任务相关时注入。当前任务的明确要求始终优先于历史偏好。

## 边界与约束

- 不自动修改 `AGENTS.md`、`CLAUDE.md`、`BRIDGE_RULES.md` 或 Memory 文件。
- 偏好只保存结构化安全字段，不保存完整用户原文、凭据、token 或敏感路径。
- 默认阈值为来自两个不同任务、30 天内的重复表达；同一任务/事件去重。
- 偏好提示不阻塞任务执行；后台标签页的候选在切回时可见。
- 项目偏好覆盖全局偏好；当前任务明确要求覆盖两者。

## 目标设计

1. `gateway/user-preferences.mjs` 提供候选识别、归一化、去重、相关性过滤和安全存储。
2. `gateway/index.mjs` 在桌面与 IM 用户输入去重后观察候选；提供偏好查询、接受、忽略、删除和更新 API；通过 WebSocket 推送候选并处理用户选择。
3. SDK 输入解析处只注入与任务类别相关的短摘要，避免普通问答增加上下文。
4. `WorkspaceView.vue` 增加轻量提示条和操作状态；`SettingsView.vue` 增加偏好列表管理。
5. 新增纯函数、持久化、Gateway 接线和 UI 状态测试。

## 验收

- 两个不同任务都明确要求 UTF-8 后出现一次候选；同一任务重复发送不重复计数。
- 选择项目/全局后可读取、禁用、删除，并在重启后保留；损坏存储不会阻塞 Gateway。
- 简单问答不注入偏好；代码修改任务注入 UTF-8 偏好；用户本轮要求冲突时不被覆盖。
- 桌面端能显示候选并完成四种操作，窄窗口不溢出；API/WebSocket 失败有明确错误。
- `node --test` 全量 Gateway、`vue-tsc`、Vite build、`git diff --check` 通过。
