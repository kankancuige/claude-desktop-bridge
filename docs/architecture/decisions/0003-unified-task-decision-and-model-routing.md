# ADR 0003：统一任务决策与模型路由

Checklist: 25/25 complete
Incomplete: None

**Status:** Accepted
**Date:** 2026-08-13
**Owner:** Claude Desktop Bridge maintainer

## Context

当前 Context Profile、Workflow 关键词、模型档位和代码审查风险分别判断任务。桌面端又在创建会话和每轮消息中显式发送模型，导致 Gateway 的自动模型路由通常不会生效。相同任务可能得到互相冲突的上下文、Workflow、模型和最终审查等级。

## Drivers

- 简单探索使用低成本模型，普通实现使用均衡模型，高风险设计与最终审查使用最强模型。
- 安全、并发、持久化、协议和会话生命周期不能因为提示短而降级。
- 旧桌面端和 IM 适配器必须保持兼容，不能修改 transcript 或会话身份格式。
- 决策原因必须可见、可测试、可审计，但不得泄漏隐藏 Prompt 或凭据。

## Options

1. 保持各模块独立判断：改动最小，但冲突和绕过问题继续存在。
2. 只修复桌面端不发送模型：能让现有长度规则生效，但长度不是可靠风险信号，Workflow 与审查仍不一致。
3. Gateway 建立统一 `TaskDecision`，所有执行面消费同一结果：边界清楚，可测试且能兼容旧客户端，但需要一次跨模块接线。

## Decision

采用方案 3。Gateway 是任务决策和自动模型选择的唯一所有者。桌面端发送 `modelMode` 表达自动或固定意图；旧客户端未发送 `modelMode` 且携带 `model` 时视为固定模式。统一决策采用“用户约束 > 硬风险 > 动作与范围 > 辅助文本信号”的优先级，并产生稳定原因码。

模型档位与思考等级分离。高风险和 Critical 任务强制使用 Power 做方案或最终审查；确定性验证继续由工具完成。Power 不承担目录枚举、日志搬运和格式扫描等机械工作。

自动模式的新空会话采用懒启动：创建标签时不提前绑定默认模型，首条消息完成任务分级和供应商兼容校验后再创建 SDK Query。恢复和分支会话不延迟模型校验。附件只提供存在、类型和文件名证据，不读取附件正文参与路由，避免文档内容操纵模型档位。

主会话是实施、操作和重构任务的唯一写入者，自动 Workflow 不得与主会话并行重复修改工作区。只读审查、调研和方案任务可自动启动辅助 Workflow；高风险实施仅在主回合成功且生成真实 checkpoint 差异后启动 Power 只读复核。最终复核由 Runner 父级强制 `plan` 权限，Workflow 内部 Agent 不能提升为写入权限。

## Consequences

- 正面：普通会话、IM、Workflow、Agent 和最终审查共享一致的任务语义；自动切换原因可见；短提示不再掩盖硬风险；自动空会话不再为未发生的任务提前启动错误模型。
- 负面：自动模式可能在回合边界触发 Query 重建；模型档位配置错误会显式暴露为降级提示。
- 中性：三个档位可以暂时映射到同一个实际模型，功能仍正确但不会产生能力或成本差异。
- 兼容：旧客户端继续固定模型；现有 `modelTiers` 文件结构保留并新增模式字段，不修改历史会话。

## Validation

- 决策纯函数覆盖简单查询、只读分析、普通修改、硬风险短句、高风险审查、继续任务和附件/代码证据。
- Gateway 测试证明自动模式使用档位模型、固定模式不被覆盖、缺少档位时显式回退。
- Workflow 测试证明档位模型传给未显式指定模型的 Agent，高风险最终审查使用 Power。
- Desktop 测试和构建证明自动/固定状态随 tab 保存，`task_decision` 可见且不清空对话。
- 进行中的补充消息继承当前回合模型；Codex Relay 不兼容配置在接受消息前阻断，禁止静默替换。
- 实施任务不会自动并行启动写入型 Workflow；Power 最终复核只消费成功回合的真实变更文件。

## Review Triggers

- 供应商增加可查询的模型能力元数据或价格策略。
- SDK 支持无需重建 Query 的回合级模型覆盖。
- 路由错误率、额外延迟或 Power 使用率超出产品可接受范围。
- 新增第四种职责模型或跨供应商自动降级。
